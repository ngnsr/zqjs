# The ZQJS language

ZQJS is a **deliberately limited JavaScript-like language**. This document defines what we
promise. Anything not listed here is not part of the language, even if it happens to work.

Three layers are kept apart:

- **ZQJS language**: this document; grows milestone by milestone.
- **ZQJS runtime**: VM, heap, objects, host API (see ARCHITECTURE.md).
- **ECMAScript compatibility**: measured (number of differential tests passing), never claimed.

## 1. The compatibility contract

Every program ends in exactly one outcome (DESIGN_DECISIONS D14):

| outcome | promise |
|---|---|
| **ok** | node accepts the program and prints the same stdout and the same uncaught error *name* |
| **SyntaxError** | node also rejects the program with a SyntaxError |
| **Unsupported(feature)** | no promise: the program is outside ZQJS. Terminates the script; **cannot be caught** by JS code |
| **LimitExceeded(limit)** | a configured resource limit was hit. Terminates the script; cannot be caught |

**Asymmetric default.** We report `SyntaxError` only when certain that node rejects the program.
When in doubt we report `Unsupported`, which makes no claim and therefore can't be wrong.

**Not compared with node, ever:** error *messages*, stack traces, `console.log` formatting
(ZQJS has `print`, which uses `String(x)`), resource-limit thresholds, timing.

**Engines.** ZQJS has two engines that must behave identically: the bytecode VM (the default)
and the tree-walking reference interpreter (`--engine=treewalk`). Between them, outputs,
exception names *and* messages, and Unsupported features must match (checked by differential
tests and fuzzing). Limit thresholds are not a cross-engine guarantee: `max_steps` counts VM
instructions on the VM and statements/expressions/iterations on the tree-walker, and the VM
allocates fewer strings, so the same script can hit a limit at a different point, or only on
one engine (DESIGN_DECISIONS D35).

**Memory.** Unreachable values are reclaimed by a garbage collector (M8), so `max_heap_bytes`
bounds live data plus garbage not yet collected: a program whose live data fits runs as long as
its step budget allows. Collections happen between instructions (between evaluation steps in
the tree-walker), so one step that allocates more than the room left can still stop with
`LimitExceeded(heap_bytes)` although garbage could be reclaimed (DESIGN_DECISIONS D8).

**Known deviation:** `**` is "implementation-approximated" in the spec. ZQJS's result is
correctly rounded in 99.9% of cases and always within 1 ulp; node's (V8's) is correctly rounded
in about 92%. So where node is 1 ulp off, ZQJS prints a different last digit
(`0.5 ** -0.5` → ZQJS `1.4142135623730951`, the correctly rounded √2; node `1.414213562373095`).
Special values and exactly representable results always match (DESIGN_DECISIONS D25).

How it is checked: `tests/diff/*.js` are whole programs whose output must equal node's
(`tests/diff/*.out`, generated by node). `tests/syntax/cases.jsonl` lists inputs with their
expected outcome.
`zig build test` checks ZQJS against it; `zig build check-goldens` checks node against it
(every `ok` must run in node without a SyntaxError, every `syntax` must raise one; scripts
are *run*, not just parsed, because some SyntaxErrors only appear when a script starts).

## 2. Unsupported features

Each `Unsupported` diagnostic names one of these stable ids.
**Restrictions** are permanent by design. **Not yet** means planned or undecided.

| id | kind | examples | why |
|---|---|---|---|
| `asi` | restriction | `1 + 2` at end of file, `1\n2;` | statements must end with `;`. ASI rules are a classic source of surprises |
| `loose_equality` | restriction | `a == b`, `a != b` | use `===`/`!==`. Avoids the abstract-equality coercion table |
| `legacy_octal` | restriction | `017`, `09`, `'\1'`, `'\08'` | sloppy-mode legacy syntax |
| `non_ascii_source` | restriction | `é = 1`, NBSP outside strings | identifiers and whitespace are ASCII only. Non-ASCII is fine inside strings and comments |
| `invalid_utf8` | restriction | malformed bytes in the source file | source must be valid UTF-8 |
| `bigint` | retired (M47) | *(implemented in M47)* | retained in `diag.Feature` enum for stability; `10n` / `BigInt` are now supported |
| `global_assignment` | restriction | `y = 1`, `undefined = 1`, `y++` with no declaration of `y` | sloppy JS silently creates (or ignores writes to) globals; ZQJS forbids implicit global writes |
| `function_to_string` | not yet | `print(print)`, `'' + f`, `f < 'a'`, `f < g` | JS converts a function to its source text; ZQJS has none to show or compare |
| `block_function` | restriction | `{ function f() {} }`, `if (c) function f() {}` | sloppy-mode Annex B gives block-level function declarations two bindings; declare functions at the top of a script or function body, or use `let f = function () {}` |
| `duplicate_parameter` | restriction | `function f(a, a) {}` | legal in sloppy JS (the last one wins) |
| `duplicate_function` | restriction | `function f() {} function f() {}`, `function f(a) { function a() {} }`, `function NaN() {}` | legal in sloppy JS (the later declaration wins, or a global is redefined) |
| `function_name_assignment` | restriction | `let g = function n() { n = 1; };` | sloppy JS silently ignores the write |
| `arguments` | retired (M60) | *(implemented in M60)* | retained in `diag.Feature` enum for stability; unmapped `arguments` object is now supported |
| `builtin` | not yet | `Intl`, `WeakRef`, `FinalizationRegistry`, `eval`, `Function(...)`, … | a global or built-in member node has that ZQJS doesn't implement yet (the diagnostic names it; DESIGN_DECISIONS D39) |
| `sparse_array` | restriction (huge gaps) | `a[2000000] = x`, `a.length = 2000000` | bounded sparse arrays with holes (`[1,,2]`, `delete a[0]`, `Array(n)`, gaps `< 2^20`) are supported; huge sparse gaps (`>= 2^20`) still report `Unsupported(sparse_array)` |
| `user_conversion` | retired (M40) | *(implemented in M40)* | retained in `diag.Feature` enum for stability; `Symbol.toPrimitive`, `toString`/`valueOf`, and `toJSON` are now supported (D70) |
| `sloppy_this` | restriction | `this` at script level, `const f = o.m; f()` where `m` reads `this` | sloppy JS uses the global object (or boxes a primitive receiver) |
| `arrow_this` | retired (M31) | *(implemented in M31)* | retained in `diag.Feature` enum for stability; lexical `this` in arrows is now supported (D62) |
| `function_properties` | retired (M31) | *(implemented in M31)* | retained in `diag.Feature` enum for stability; functions are first-class objects (D62) |
| `primitive_write` | restriction | `'s'.x = 1`, `delete 'ab'.length` | sloppy JS silently ignores these |
| `regex_annex_b` | restriction | `/{/`, `/(?=a)*/`, `/\8/` | Annex B web-reality RegExp syntax |
| `regex_unicode_escape_braced` | restriction | `/\u{41}/` | `\u{...}` RegExp escapes without `u`/`v` mode (Annex B identity escape in JS) |
| `regex_unicode_property` | restriction | `/\p{ASCII}/` | `\p{...}` and `\P{...}` RegExp unicode property escapes without `u`/`v` mode (Annex B identity escape in JS) |
| `syntax` | not yet | `with`, `let` used as a variable name, `eval`, … | any JS token or construct not yet in the grammar below |

## 3. Lexical grammar (M1)

- **Source**: UTF-8 bytes, at most `Limits.max_source_bytes` (default 16 MiB).
- **Whitespace**: space, tab, `\v`, `\f`, `\n`, `\r`.
- **Comments**: `// …` to end of line; `/* … */` (unterminated → SyntaxError).
- **Numbers**: `DecimalDigits [. DecimalDigits?] [ (e|E) [+|-] DecimalDigits ]`,
  `. DecimalDigits [exponent]`, or `0x`/`0X` hex, `0o`/`0O` octal and `0b`/`0B` binary integers
  (M21.1). `_` separators are allowed only between two digits (`1_000`, `0xff_ff`, `1e1_0`;
  `1__0`, `1_`, `1_.5`, `0_1`, `0x_1` → SyntaxError). Leading `0` followed by a digit →
  `Unsupported(legacy_octal)` (a SyntaxError in strict-mode JS too). `e` or a radix prefix
  without digits → SyntaxError. A number immediately followed by an identifier character or
  digit → SyntaxError (`3in`, `1.5.3`, `0b12`), except `n` (`bigint`). Values are IEEE-754
  doubles, correctly rounded (radix integers longer than 53 bits too); overflow gives `Infinity`.
- **Strings**: `'…'` or `"…"`, decoded to **UTF-16 code units**. A raw line feed or carriage
  return inside the literal → SyntaxError. Escapes:

  | escape | result |
  |---|---|
  | `\b \f \n \r \t \v` | the usual control characters |
  | `\0` (not followed by a digit) | U+0000 |
  | `\xHH` | one code unit (exactly 2 hex digits, else SyntaxError) |
  | `\uHHHH` | one code unit; **lone surrogates allowed** (`'\uD800'` has length 1) |
  | `\u{H…}` | code point ≤ 10FFFF (else SyntaxError); above FFFF → surrogate pair |
  | `\` + line terminator (LF, CR, CRLF, U+2028, U+2029) | nothing (line continuation) |
  | `\1`–`\9`, `\0` + digit | `Unsupported(legacy_octal)` |
  | `\` + any other character | that character (`'\q'` is `"q"`) |

  Non-ASCII characters in the literal are decoded from UTF-8; those above U+FFFF become a
  surrogate pair, so `'😀'`, `'\u{1F600}'` and `'\uD83D\uDE00'` are the same string.
- **Identifiers**: `[A-Za-z_$][A-Za-z0-9_$]*`, ASCII only.
- **Keywords**: `true false null const if else while for break continue`. `let` is *not* a
  keyword (it isn't one in sloppy JS); it introduces a declaration only when followed by a
  binding name (§4). Other JS reserved words (`this`, `new`, `var`, `function`, …) are
  `Unsupported(syntax)` where an expression is expected, and a SyntaxError as variable names.

## 4. Syntactic grammar (M2, functions M6)

```
Script            := BodyItem*
BodyItem          := FunctionDeclaration | StatementListItem   (script and function bodies)
FunctionDeclaration := 'async'? 'function' Identifier Params Body   (hoisted; not inside blocks; no line break after 'async')
Params            := '(' (Param (',' Param)* ','?)? ')'
Param             := '...' BindingPattern | BindingPattern ('=' Expression)?
Body              := '{' BodyItem* '}'
StatementListItem := Declaration | Statement
Declaration       := ('let' | 'const') Declarator (',' Declarator)* ';'
Declarator        := BindingPattern ('=' Expression)?     (const and destructuring require '=')
BindingPattern    := Identifier
                   | '[' (ArrayPatElem? (',' ArrayPatElem?)* (',' '...' BindingPattern)?)? ']'
                   | '{' (ObjPatProp (',' ObjPatProp)* (',' '...' Identifier)? ','?)? '}'
ArrayPatElem      := BindingPattern ('=' Expression)?
ObjPatProp        := Identifier ('=' Expression)? | PropertyKey ':' BindingPattern ('=' Expression)?
Statement         := ';'                                   (empty statement)
                   | '{' StatementListItem* '}'            (block)
                   | 'if' '(' Expression ')' Statement ('else' Statement)?
                   | 'while' '(' Expression ')' Statement
                   | 'do' Statement 'while' '(' Expression ')' ';'
                   | 'switch' '(' Expression ')' '{' CaseClause* '}'
                   | 'for' '(' ForInit? ';' Expression? ';' Expression? ')' Statement
                   | 'break' ';' | 'continue' ';'          (break in loop/switch; continue in loop)
                   | 'return' Expression? ';'              (only inside a function)
                   | 'throw' Expression ';'
                   | 'try' Block (('catch' ('(' BindingPattern ')')? Block) ('finally' Block)? | 'finally' Block)
                   | Expression ';'
CaseClause        := ('case' Expression | 'default') ':' StatementListItem*
ForInit           := ('let' | 'const') Declarator (',' Declarator)* | Expression
Expression        := Target AssignOp Expression | Pattern '=' Expression | ArrowFunction | Logical   (right-associative)
ArrowFunction     := 'async'? (Identifier | Params) '=>' (Body | Expression)   (no line break before '=>' or after 'async')
AssignOp          := '=' | '+=' | '-=' | '*=' | '/=' | '%=' | '**='
                   | '<<=' | '>>=' | '>>>=' | '&=' | '^=' | '|=' | '&&=' | '||=' | '??='
Logical           := Logical ('||' | '&&') Logical          (&& binds tighter than ||; cannot mix with ??)
                   | Coalesce
Coalesce          := Coalesce '??' BitOr | BitOr
BitOr             := BitOr '|' BitXor | BitXor
BitXor            := BitXor '^' BitAnd | BitAnd
BitAnd            := BitAnd '&' Equality | Equality
Equality          := Equality ('===' | '!==') Relational | Relational
Relational        := Relational ('<' | '<=' | '>' | '>=' | 'in') Shift | Shift
Shift             := Shift ('<<' | '>>' | '>>>') Additive | Additive
Additive          := Additive ('+' | '-') Mult | Mult
Mult              := Mult ('*' | '/' | '%') Exp | Exp
Exp               := Unary | Postfix '**' Exp               (right-associative)
Unary             := ('-' | '+' | '!' | '~' | 'typeof') Unary | 'await' Unary (only in an async function body) | ('++' | '--') Unary | 'delete' Member | Postfix
Postfix           := Primary ('++' | '--')?                 (no line break before ++/--)
Primary           := Number | String | Template | 'true' | 'false' | 'null' | Identifier
                   | '[' (ArgItem (',' ArgItem)* ','?)? ']'             (array, no holes)
                   | '{' (PropDef (',' PropDef)* ','?)? '}'            (object)
                   | 'this'                                (only inside functions)
                   | 'async'? 'function' Identifier? Params Body    (function expression)
                   | '(' Expression ')'
                   | Primary '(' (ArgItem (',' ArgItem)* ','?)? ')'   (call)
                   | Primary '.' IdentifierName | Primary '[' Expression ']'   (member)
                   | Primary '?.' (IdentifierName | '[' Expression ']' | '(' (ArgItem (',' ArgItem)* ','?)? ')')   (optional chain)
ArgItem           := '...'? Expression
PropDef           := (IdentifierName | String | Number | '[' Expression ']') ':' Expression
                   | '...' Expression                      (spread)
                   | Identifier                            (shorthand) | IdentifierName Params Body (method)
```

Notable rules, all matching JavaScript:
- `2 ** 3 ** 2` is `2 ** (3 ** 2)` = 512. `1 < 2 < 3` is legal (left-associative).
- `-`, `+`, `!` or `~` directly before `**` is a **SyntaxError** (`-2 ** 2`, `~2 ** 2`, `2 ** -2 ** 2`);
  `(-2) ** 2`, `2 ** -2`, `++x ** 2` and `x++ ** 2` are fine.
- Assignment and `++`/`--` targets must be identifiers, possibly parenthesised (`(x) = 1`);
  `1 = 2`, `x + 1 = 2`, `++1`, `(x + 1)++` are SyntaxErrors.
- `let` + binding name starts a declaration, even across a line break (`let\nx = 1`).
  A declaration where only a single statement is allowed (`if (c) let x = 1;`,
  `while (c) const y = 1;`) is a SyntaxError.
- **`break` / `continue`** (all three cases are distinct in JS):

  | input | meaning in JS | ZQJS |
  |---|---|---|
  | `break;` outside a loop | error | SyntaxError |
  | `break foo;` | jump to label `foo` | `Unsupported(labels)`, even outside a loop: `foo: { break foo; }` is valid |
  | `break\nfoo;` | ASI: `break; foo;` | `Unsupported(asi)` inside a loop; SyntaxError outside one |

Nesting deeper than `Limits.max_nesting_depth` (default 512) → `LimitExceeded(nesting_depth)`.
The limit bounds the parser's recursion (each parenthesis level costs two, each nested
statement or `=` one) and the depth of expression trees (operator chains).

A script whose bytecode exceeds `Limits.max_code_bytes` (default 64 MiB) →
`LimitExceeded(code_bytes)`; more than `Limits.max_constants` (default 2^20) distinct literals,
or as many distinct variable names → `LimitExceeded(constants)`. Both are reported before the
script runs (DESIGN_DECISIONS D32).

## 5. Semantics

### Values and globals (M3)
Values: `undefined`, `null`, booleans, numbers (IEEE-754 doubles), strings (UTF-16 code units),
native functions and (M6) closures. Globals: `undefined`, `NaN`, `Infinity`, and `print(a, b, …)`, which
writes `String(a) + ' ' + String(b) + … + '\n'` (lone surrogates are written as U+FFFD).
Calling anything other than a function throws a **TypeError** (after the arguments are
evaluated); reading an undeclared global throws a **ReferenceError**.

### Functions (M6), as in JavaScript
- **Calls:** the callee, then the arguments left to right, then the callable check. Missing
  arguments are `undefined`; extra ones are evaluated and dropped. `return;`, `return e;`, and
  falling off the end (`undefined`).
- **Declarations** at the top of a script or function body are hoisted *and initialised* on
  entry, so `f(); function f() {}` and mutual recursion work. Their names are mutable bindings.
- **Named function expressions:** the name is bound only inside the function, to the function;
  parameters and locals may shadow it.
- **Closures** capture *bindings*, not values: writes through one closure are seen by every
  other closure of the same binding, and a binding lives as long as any closure using it.
  Every execution of a block creates new bindings (`{ let x = …; f = function () { return x; }; }`
  run twice gives two independent `x`s).
- **`for (let …)`** gives each iteration its own copy of the head bindings: a closure created in
  an iteration keeps that iteration's value, even after later iterations or the update run.
- **Values:** functions compare by identity (`===`), are truthy, and convert to NaN. Converting
  one to a string, or comparing it with a string or another function, needs its source text:
  `Unsupported(function_to_string)`.
- **Arrow functions (M20, M26):** `x => expr`, `(x) => expr`, `() => expr`, `(a, b) => expr`,
  pattern/default/rest parameters (`({a}) => a`, `([a, b]) => a + b`, `(a = 1) => a`, `(...r) => r`),
  `x => { body }`, `(a, b) => { body }`, and `x => ({ a: 1 })` (parenthesised object-literal
  bodies). An expression body returns its value; a block body returns `undefined` unless
  `return` executes. A line terminator before `=>` is a SyntaxError. Arrow functions share
  closure and parameter rules with function expressions (`duplicate_parameter` for simple lists,
  `SyntaxError` for duplicates in non-simple lists), throw `TypeError` on `new`, and
  fail at resolve time with `Unsupported(arrow_this)` if `this` is read inside an arrow body
  (outside a nested regular `function`).
- **Default & rest parameters (M26):** `function f(a, b = a + 1, ...r)` and arrow equivalents.
  Defaults are evaluated lazily left to right when the argument is `undefined`, in a parameter
  scope isolated from body `let`/`const` declarations; referring to a later parameter eagerly is a
  TDZ `ReferenceError`. Rest parameters must be last, have no default, and have no trailing comma.
- **Limits:** more than `Limits.max_call_depth` (default 10,000) active calls →
  `LimitExceeded(call_depth)` (node: RangeError at about 11,000). The VM also limits the stack
  slots reserved by all active frames (`max_stack_slots`), the tree-walker its evaluation
  nesting (`max_interpreter_depth`); which limit a runaway recursion hits first is engine-specific.

### Operators (M3), as in JavaScript
- Operands are evaluated left to right; `&&`/`||`/`??` short-circuit and return an operand value (`??` only evaluates the right side when the left is `null` or `undefined`). Optional chaining (`?.`) short-circuits the rest of the chain to `undefined` (`true` for `delete`) when the base is `null` or `undefined`, preserving `this` on optional method calls.
- `+` concatenates if either side is a string, otherwise adds numbers. `- * / % **` and unary
  `-`/`+` convert to numbers (`+'0x10'` is 16, `+'1_000'` is NaN, `+''` is 0).
- `<` `<=` `>` `>=` compare two strings by UTF-16 code unit, anything else as numbers.
- `===`/`!==`: same type and value; `NaN !== NaN`, `0 === -0`.
- `-0` is kept through arithmetic and prints as `0`.

### Objects and arrays (M7), as in JavaScript
- **Literals:** `{ a: 1, 'b c': 2, 3: x, [k]: v, short, method() {…} }`: each (computed) key,
  then its value, left to right; a repeated key keeps its first position and its last value.
  `[a, b, ]` (no holes).
- **Members:** `o.name`, `o[expr]`; the base, then the key expression, are evaluated exactly once
  for reads, writes, `op=` and `++`/`--`. The key is *converted* (ToPropertyKey) when first used:
  for `o[k] = v` after `v` is evaluated, for `o[k] op= v` at the read, before `v`. Reading a
  property of `undefined`/`null` is a TypeError; so is writing one (after the right-hand side).
- **Keys:** strings; numbers become strings (`-0` → `"0"`, `1e21` → `"1e+21"`). `Object.keys`
  lists array indices (canonical numbers up to 2^32 − 2) ascending, then other keys in insertion
  order; deleting and re-adding a key moves it to the end.
- **Arrays:** dense (`sparse_array`). `length` reads the element count; setting it smaller
  truncates, an invalid length is a RangeError. `push`, `pop`, `join`.
- **Prototypes:** reads, `in` and method lookups follow the chain; writes create own properties.
  `Object.create(proto | null)`, `Object.getPrototypeOf`. Chains can't contain cycles (the only
  way to change a prototype, `__proto__`, is Unsupported).
- **Conversions:** `String(o)` is `[object Object]`, arrays join with `,` (nested arrays flatten;
  `null`/`undefined` elements are empty; a cycle is empty), `+[5]` is 5, `[] + {}` is
  `[object Object]`, `===` compares identity.
- **Strings:** `s.length` and `s[i]` count UTF-16 code units (a surrogate pair is 2);
  `s.charCodeAt(i)` returns a code unit (NaN out of range). `s.toLowerCase()` and
  `s.toUpperCase()` only handle ASCII (`< 0x80`); any non-ASCII code unit (`>= 0x80`)
  fails explicitly with `Unsupported(builtin)` rather than leaving it unchanged.
- **`this`:** the receiver of a method call; see `sloppy_this` and DESIGN_DECISIONS D41.
- **`delete o.k`** and **`k in o`** (`in` on a non-object is a TypeError).
- **Built-ins:** only those listed in DESIGN_DECISIONS D39 (plus M11–M25 additions below); every other name node has is `Unsupported(builtin)`, every name node doesn't have is `undefined` / a ReferenceError.
- **Errors & `instanceof` (M25):**
  - Constructors: `Error`, `TypeError`, `RangeError`, `SyntaxError`, `ReferenceError`, `EvalError`, `URIError`, and `AggregateError` (callable with and without `new`). When `msg !== undefined`, own non-enumerable `message = ToString(msg)` is set; `{ cause }` sets own non-enumerable `cause` when `options` is an object with `"cause"` in its prototype chain. `AggregateError(errors, msg[, options])` collects `errors` via the built-in iterable protocol into a non-enumerable `errors` array.
  - Prototypes: `Error.prototype` (`name: "Error"`, `message: ""`, `constructor: Error`, `toString`) inherits from `Object.prototype`; each subclass prototype (`TypeError.prototype`, etc.) inherits from `Error.prototype` with its own `name`, `message: ""`, and `constructor`, and is exposed as `C.prototype`.
  - `Error.prototype.toString` follows ECMAScript (`"Name: msg"`, `"Name"`, `"msg"`, `""`) and is an allowed built-in conversion under D40 (`String(e)`, `"" + e`, `` `${e}` ``, `print(e)`). Engine-thrown errors (`catchValue`), `Promise.any` (`AggregateError`), and `Promise` self-resolution (`TypeError`) materialize as real instances of these constructors while keeping host/CLI uncaught-error reports and uncatchable `LimitExceeded`/`OutOfMemory` semantics unchanged.
  - `x instanceof C`: relational precedence, throws `TypeError` if `C` is not callable or is a built-in non-constructor without a prototype (`parseInt`), fails with `Unsupported(function_properties)` if `C` is a user-defined function, returns `false` for primitives on the left, and walks `x`'s prototype chain against `C.prototype` for built-in constructors (`Object`, `Array`, `String`, `Number`, `Map`, `Set`, `Promise`, and the `Error` family).
- **Everyday built-ins (M23):**
  - `String.prototype`: `split(sep[, limit])` (string separator only; `undefined` → `[s]`; `""` → UTF-16 code units), `trim`, `trimStart`, `trimEnd` (JS whitespace incl. `U+FEFF`, `U+00A0`, line terminators), `startsWith`, `endsWith`, `repeat` (`RangeError` on negative/`Infinity`; bounded by `Limits.max_string_length`), `padStart`, `padEnd`, `substring`, `lastIndexOf`, `at`, `replace`, and `replaceAll` (string patterns; `$$`, `$&`, `` $` ``, `$'`, or function replacer via `callCallable`; `replaceAll("", ...)` inserts between code units).
  - `Array.prototype`: `find`, `findIndex`, `findLast`, `findLastIndex`, `some`, `every`, `concat`, `reverse`, `at`, `lastIndexOf`, `fill`, `shift`, `unshift`, `splice`, and `sort([compare])` (stable, `undefined` last, default UTF-16 `ToString` order; comparator runs on a rooted snapshot and writes back at the end, so throwing comparators leave the array unchanged and mutations never corrupt or go out of bounds).
  - `Object`: `Object.values`, `Object.entries`, `Object.assign(target, ...sources)` (own enumerable string-keyed data properties in `Object.keys` order; `null`/`undefined` target throws `TypeError`, primitive target is `Unsupported(builtin)`).
  - Globals & `Number` / `Array` statics: `String(x)` and `Number(x)` (conversion only; `new String`/`new Number` stay `Unsupported(builtin)`), `parseInt(s, radix)`, `parseFloat(s)`, `isNaN`, `isFinite`, `Number.isInteger`, `Number.isFinite`, `Number.isNaN`, `Number.isSafeInteger`, `Number.{MAX_SAFE_INTEGER, MIN_SAFE_INTEGER, EPSILON, MAX_VALUE, MIN_VALUE, POSITIVE_INFINITY, NEGATIVE_INFINITY, NaN}`, `Array.from(iterable[, mapFn[, thisArg]])` (via built-in iterators), `Array.of`.
- **Collections & Iterators (M14):**
  - `new`: supported for `Map`, `Set`, and `Promise` (`new` on user functions or other built-ins like `Object`/`Array` is `Unsupported(builtin)`; non-constructors throw `TypeError`).
  - `Map` & `Set`: insertion-ordered `OrderedTable` with SameValueZero equality (`NaN` matches `NaN`, `-0 === +0`, UTF-16 string equality, pointer identity for objects/functions), read-only `size`, `get`/`set`/`has`/`delete`/`clear` (`Map`) and `add`/`has`/`delete`/`clear` (`Set`), plus `keys`/`values`/`entries`. `forEach` and `WeakMap`/`WeakSet` are `Unsupported(builtin)`.
  - `for...of` & Iterators: `for (let|const|id of iterable)` over `Array`, `Map`, `Set`, `String` (code-point surrogate pairs + lone surrogates), and built-in iterators (`Iterator.prototype.next`). Live `Map`/`Set` mutations (including `clear()` followed by insertion) are visible to active iterators; exhausted iterators stay `done: true`. `Symbol.iterator` and destructuring targets remain `Unsupported`.
- **JSON (M15):**
  - `JSON.parse(text [, reviver])`: UTF-16 recursive-descent parser enforcing strict JSON whitespace and number grammar, `\uXXXX` escapes (preserving surrogate pairs and lone surrogates), `"__proto__"` as an own data property, catchable `SyntaxError`, and `Limits.max_nesting_depth` / `Limits.max_string_length`. Non-callable `reviver` values are ignored; callable `reviver` fails with `Unsupported(user_conversion)`.
  - `JSON.stringify(value [, replacer [, space]])`: serializes primitives, dense arrays (`undefined`/functions → `null`), and ordinary objects in `Object.keys` order (`undefined`/functions omitted; `Map`/`Set` → `"{}"`), `NaN`/`±Infinity` → `null`, `-0` → `"0"`, control-char and lone-surrogate escaping, active-ancestor cycle detection (`TypeError`), and `Limits.max_nesting_depth` / `Limits.max_string_length`. Non-callable/non-array `replacer` values are ignored; callable/array `replacer`, non-`undefined` `space`, and own/inherited callable `toJSON` properties fail explicitly (`Unsupported`).
- **Callback-taking built-ins (M16):**
  - `Array.prototype.forEach`, `Array.prototype.map`, `Array.prototype.filter`, `Array.prototype.reduce`, `Map.prototype.forEach`, and `Set.prototype.forEach` invoke JS callbacks reentrantly on both engines (`thisArg` follows ZQJS sloppy `this` rules: object receivers bind `this`, while reading `this` with primitive/`null`/`undefined` `thisArg` fails with `Unsupported(sloppy_this)` per D41).
  - Array callbacks capture the initial length at entry; growing the array does not extend iteration, and shrinking skips missing indices for `forEach`, `filter`, and `reduce`. **Intentional deviation:** if a callback shrinks the array during `Array.prototype.map`, ZQJS fails with `Unsupported(sparse_array)` rather than producing sparse holes (arrays are always dense per D13).
  - `Map.prototype.forEach` and `Set.prototype.forEach` visit entries in insertion order and observe live mutations during iteration (deletes, updates, additions, `clear()` followed by insertion, and delete + reinsert of the current entry).
- **Promises & microtasks (M18–M19):**
  - `new Promise(executor)`, `Promise.resolve(v)`, `Promise.reject(r)`, `Promise.prototype.then(onFulfilled, onRejected)`, `Promise.prototype.catch(onRejected)`, and `Promise.prototype.finally(onFinally)`. Calling `Promise(...)` without `new` or passing a non-callable executor throws `TypeError`; self-resolution rejects with `TypeError`.
  - `Promise.prototype.finally(onFinally)` passes through non-callable handlers like `then(f, f)` and invokes callable handlers with 0 arguments, preserving the original value/reason unless `onFinally` throws or returns a rejected promise.
  - Combinators: `Promise.all(iterable)`, `Promise.allSettled(iterable)`, `Promise.race(iterable)`, and `Promise.any(iterable)` iterate with the built-in iterable protocol (`Array`, `String`, `Map`, `Set`, `Iterator`), wrapping non-promise elements via `Promise.resolve(x)` and rejecting the returned Promise with `TypeError` on non-iterable arguments. `Promise.any` rejects with an `AggregateError`-like `Error` object (`name: "AggregateError"`, `message: "All promises were rejected"`, and an `errors` array property) when all inputs reject or the iterable is empty.
  - `resolve`/`reject` capabilities share an `already_resolved` guard; synchronous exceptions thrown by `executor` reject the Promise if not already resolved.
  - **Native-only adoption (intentional limitation):** resolving with a native ZQJS `Promise` adopts its state via microtasks. Arbitrary thenables (objects with a `.then` property or accessor) are **not** inspected or assimilated and fulfill directly with that value.
  - **Microtask checkpoints & fault semantics:** `Runtime.microtasks` drains in FIFO order at the end of each outermost `run`/`call` turn (nested/reentrant calls do not drain early). Caught JS exceptions inside reactions reject the child Promise. Uncatchable runtime faults (`LimitExceeded`, `OutOfMemory`, etc.) consume the active microtask without retry (leaving its child Promise pending), preserve remaining queued microtasks, and propagate cleanly so a later valid checkpoint can resume draining.
  - **Deferred / out of scope:** `Promise.withResolvers`, `Promise.try`, unhandled-rejection tracking, and `Symbol.species` subclassing.
- **`async` / `await` (M28b, both engines, D56/D59):**
  - `async function` declarations and expressions, async arrows (`async x => …`, `async (a, b) => …`, every parameter form), and async methods in object literals (`{ async m() {} }`). `async` stays an ordinary identifier elsewhere; a line break after `async` makes it the plain identifier.
  - `await e` (precedence of `typeof`) only directly inside an async function's body. `await` in an async function's parameters, or `await` as a binding name inside one, is a `SyntaxError`; `await` outside async functions (script top level, non-async functions), async generators and `for await` are `Unsupported(syntax)`.
  - Calling an async function returns a native `Promise`: the body runs synchronously up to its first `await`; a `return` resolves the promise (adopting a returned native promise in two extra ticks, as in node), and an uncaught exception, including one thrown before any `await`, rejects it. `new` on an async function throws `TypeError`.
  - `await v` converts `v` with `Promise.resolve` (native-only adoption, as above) and resumes in exactly one microtask once it settles; a rejection is thrown at the `await`, so `try`/`catch`/`finally` around it work, including a pending `return` held across an `await` inside `finally`'s region.
  - Limits: step, call-depth and interpreter-depth limits apply to async calls and to resumed ones; each pending async call's suspended state is charged to `max_heap_bytes`. An uncatchable fault inside an async call leaves its promise pending (as for reactions).
- **`RegExp` (M30, extended in M32, both engines, D61):**
  - Literals (`/pattern/flags`) and `RegExp(pattern[, flags])` / `new RegExp(pattern[, flags])`: every literal evaluation creates a fresh `RegExp` object with `lastIndex = 0`; `RegExp(re)` returns `re` unchanged when `flags === undefined`, while `new RegExp(re)` clones it and `RegExp(re, flags)` recompiles with new flags. Empty pattern has `.source === "(?:)"`.
  - Flags: `d` (`hasIndices`), `g` (`global`), `i` (`ignoreCase`, full Unicode and legacy non-`u` case folding), `m` (`multiline`), `s` (`dotAll`), `u` (`unicode`), `v` (`unicodeSets`), `y` (`sticky`). Annex B regex syntax reports `Unsupported(regex_annex_b)` (or `regex_unicode_escape_braced` / `regex_unicode_property` outside `u`/`v` mode).
  - Instance properties & methods: writable `lastIndex` (non-configurable, `delete re.lastIndex === false`), read-only `source`, `flags` (sorted `"dgimsuvy"`), `hasIndices`, `global`, `ignoreCase`, `multiline`, `dotAll`, `unicode`, `unicodeSets`, `sticky` (`Object.keys(re)` is `[]`), `re instanceof RegExp`, `RegExp.prototype.exec(str)` (returns `[full, cap1, …]` with `.index`, `.input`, `.groups`, and `.indices` when `d` is set, or `null`, updating `lastIndex` on `g`/`y`), `RegExp.prototype.test(str)`, and `RegExp.prototype.toString()`.

### Bindings

**Static (checked now, by the resolver):**
- Each block, the script, and each `for` head is a scope. A `for` head scope encloses the
  body, so `for (let i;;) { let i; }` is legal.
- A `let`/`const` binding is visible from the *start* of its scope (hoisting), so
  `let x = 1; { x; let x = 2; }` refers to the inner `x`.
- Declaring the same name twice in one scope is a SyntaxError; shadowing an outer name is fine.
- At script level, `let`/`const` named `undefined`, `NaN` or `Infinity` is a SyntaxError
  (as in node). Inside a block or a `for` head they are ordinary names.
- Top-level bindings belong to the script; they are not shared between scripts (revisit at M9).
- A name with no declaration in scope is a *global*: reading it is allowed (M3: a
  ReferenceError if it doesn't exist), assigning to it is `Unsupported(global_assignment)`.

**Dynamic (enforced by the interpreter, checked against node in `tests/diff`):**
- **Temporal dead zone:** from scope entry until its declaration runs, reading or writing a
  binding throws a ReferenceError. `let x;` initialises to `undefined`. Each time a block is
  entered (e.g. each loop iteration) its bindings start uninitialised again.
- **`x = e`**: evaluate `e`, *then* the TDZ check, *then* the const check, then store.
  **`x op= e`** and **`++x`/`x++`**: read `x` (TDZ check) first, then evaluate the right side.
- **`const`**: writing to an initialised const binding throws a **TypeError**, only when the
  write executes (`if (false) c = 2;` is fine). It is never an early error.
- **`for (let …)`**: each iteration gets a fresh copy of the head bindings (see Functions).
- **Destructuring & spread (M26):** array patterns (`[a, , b = 1, ...r]`) consume any iterable
  through the built-in iterator machinery; object patterns (`{ a, b: c = 1, [k]: v, ...r }`) copy
  remaining own enumerable string-keyed properties in `Object.keys` order. Defaults are evaluated
  lazily left to right when the value is `undefined`; destructuring `null`/`undefined` throws
  `TypeError`. Supported in `let`/`const` declarations, function/arrow parameters, `for...of`
  heads, `catch` parameters, and plain assignment expressions (`[a, b] = [b, a]`, `({ a } = o)`).
  Spread (`...xs`) is supported in array literals, object literals (`null`/`undefined` spread
  nothing), calls (preserving `this` on method calls), and `new` calls.

### `try` / `catch` / `finally` (M11.2, M27)
- `try { ... } catch [(e)] { ... }`, `try { ... } finally { ... }`, and
  `try { ... } catch [(e)] { ... } finally { ... }`. `try {}` with neither `catch` nor
  `finally` is a `SyntaxError`, as is `finally` without `try`.
- `finally` always runs on normal completion, `return`, `break`, `continue`, and JS `throw`.
  An abrupt completion in `finally` (`return`, `break`, `continue`, `throw`) overrides the
  pending completion; otherwise the pending completion is re-performed after `finally` finishes.
- **Uncatchable faults skip `finally`:** `LimitExceeded`, `OutOfMemory`, `Unsupported`, and
  `Internal` are not JS exceptions; they skip both `catch` and `finally` and unwind directly
  to the host.
