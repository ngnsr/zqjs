# The ZQJS language

ZQJS is a **deliberately limited JavaScript-like language**. This document defines what we
promise. Anything not listed here is not part of the language, even if it happens to work.

Three layers are kept apart:

- **ZQJS language**: this document; grows milestone by milestone.
- **ZQJS runtime**: VM, heap, objects, host API (see ARCHITECTURE.md).
- **ECMAScript compatibility**: measured (number of differential tests passing), never claimed.

## 1. The compatibility contract

Every program ends in exactly one outcome (DESIGN_DECISIONS D14):

| outcome | promise |
|---|---|
| **ok** | node accepts the program and prints the same stdout and the same uncaught error *name* |
| **SyntaxError** | node also rejects the program with a SyntaxError |
| **Unsupported(feature)** | no promise: the program is outside ZQJS. Terminates the script; **cannot be caught** by JS code |
| **LimitExceeded(limit)** | a configured resource limit was hit. Terminates the script; cannot be caught |

**Asymmetric default.** We report `SyntaxError` only when certain that node rejects the program.
When in doubt we report `Unsupported`, which makes no claim and therefore can't be wrong.

**Not compared with node, ever:** error *messages*, stack traces, `console.log` formatting
(ZQJS has `print`, which uses `String(x)`), resource-limit thresholds, timing.

**Engines.** ZQJS has two engines that must behave identically: the bytecode VM (the default)
and the tree-walking reference interpreter (`--engine=treewalk`). Between them, outputs,
exception names *and* messages, and Unsupported features must match (checked by differential
tests and fuzzing). Limit thresholds are not a cross-engine guarantee: `max_steps` counts VM
instructions on the VM and statements/expressions/iterations on the tree-walker, and the VM
allocates fewer strings, so the same script can hit a limit at a different point, or only on
one engine (DESIGN_DECISIONS D35).

**Known deviation:** `**` is "implementation-approximated" in the spec. ZQJS's result is
correctly rounded in 99.9% of cases and always within 1 ulp; node's (V8's) is correctly rounded
in about 92%. So where node is 1 ulp off, ZQJS prints a different last digit
(`0.5 ** -0.5` → ZQJS `1.4142135623730951`, the correctly rounded √2; node `1.414213562373095`).
Special values and exactly representable results always match (DESIGN_DECISIONS D25).

How it is checked: `tests/diff/*.js` are whole programs whose output must equal node's
(`tests/diff/*.out`, generated by node). `tests/syntax/cases.jsonl` lists inputs with their
expected outcome.
`zig build test` checks ZQJS against it; `zig build check-goldens` checks node against it
(every `ok` must run in node without a SyntaxError, every `syntax` must raise one; scripts
are *run*, not just parsed, because some SyntaxErrors only appear when a script starts).

## 2. Unsupported features

Each `Unsupported` diagnostic names one of these stable ids.
**Restrictions** are permanent by design. **Not yet** means planned or undecided.

| id | kind | examples | why |
|---|---|---|---|
| `asi` | restriction | `1 + 2` at end of file, `1\n2;` | statements must end with `;`. ASI rules are a classic source of surprises |
| `loose_equality` | restriction | `a == b`, `a != b` | use `===`/`!==`. Avoids the abstract-equality coercion table |
| `legacy_octal` | restriction | `017`, `09`, `'\1'`, `'\08'` | sloppy-mode legacy syntax |
| `non_ascii_source` | restriction | `é = 1`, NBSP outside strings | identifiers and whitespace are ASCII only. Non-ASCII is fine inside strings and comments |
| `invalid_utf8` | restriction | malformed bytes in the source file | source must be valid UTF-8 |
| `numeric_separator` | not yet | `1_000` | |
| `non_decimal_literal` | not yet | `0x10`, `0o7`, `0b1` | |
| `bigint` | not yet | `10n` | |
| `global_assignment` | restriction (revisit at M9) | `y = 1`, `undefined = 1`, `y++` with no declaration of `y` | sloppy JS silently creates (or ignores writes to) globals; ZQJS has no writable globals yet |
| `function_to_string` | not yet | `print(print)`, `'' + f`, `f < 'a'`, `f < g` | JS converts a function to its source text; ZQJS has none to show or compare |
| `block_function` | restriction | `{ function f() {} }`, `if (c) function f() {}` | sloppy-mode Annex B gives block-level function declarations two bindings; declare functions at the top of a script or function body, or use `let f = function () {}` |
| `duplicate_parameter` | restriction | `function f(a, a) {}` | legal in sloppy JS (the last one wins) |
| `duplicate_function` | restriction | `function f() {} function f() {}`, `function f(a) { function a() {} }`, `function NaN() {}` | legal in sloppy JS (the later declaration wins, or a global is redefined) |
| `function_name_assignment` | restriction | `let g = function n() { n = 1; };` | sloppy JS silently ignores the write |
| `arguments` | not yet | `arguments`, `function f(arguments) {}` | the arguments object |
| `labels` | not yet | `foo: while (…)`, `break foo;` | |
| `syntax` | not yet | `?:`, `,`, `~`, `&&=`, `var`, `do`, destructuring, `for…of/in`, `let` used as a variable name, arrow functions, default/rest parameters, generators, `async`, `this`, `new`, regexes … | any JS token or construct not yet in the grammar below |

## 3. Lexical grammar (M1)

- **Source**: UTF-8 bytes, at most `Limits.max_source_bytes` (default 16 MiB).
- **Whitespace**: space, tab, `\v`, `\f`, `\n`, `\r`.
- **Comments**: `// …` to end of line; `/* … */` (unterminated → SyntaxError).
- **Numbers**: `DecimalDigits [. DecimalDigits?] [ (e|E) [+|-] DecimalDigits ]` or
  `. DecimalDigits [exponent]`. Leading `0` followed by a digit → `Unsupported(legacy_octal)`.
  `e` without digits → SyntaxError. A number immediately followed by an identifier character or
  digit → SyntaxError (`3in`, `1.5.3`), except `n` (`bigint`) and `_` (`numeric_separator`).
  Values are IEEE-754 doubles, correctly rounded; overflow gives `Infinity`.
- **Strings**: `'…'` or `"…"`, decoded to **UTF-16 code units**. A raw line feed or carriage
  return inside the literal → SyntaxError. Escapes:

  | escape | result |
  |---|---|
  | `\b \f \n \r \t \v` | the usual control characters |
  | `\0` (not followed by a digit) | U+0000 |
  | `\xHH` | one code unit (exactly 2 hex digits, else SyntaxError) |
  | `\uHHHH` | one code unit; **lone surrogates allowed** (`'\uD800'` has length 1) |
  | `\u{H…}` | code point ≤ 10FFFF (else SyntaxError); above FFFF → surrogate pair |
  | `\` + line terminator (LF, CR, CRLF, U+2028, U+2029) | nothing (line continuation) |
  | `\1`–`\9`, `\0` + digit | `Unsupported(legacy_octal)` |
  | `\` + any other character | that character (`'\q'` is `"q"`) |

  Non-ASCII characters in the literal are decoded from UTF-8; those above U+FFFF become a
  surrogate pair, so `'😀'`, `'\u{1F600}'` and `'\uD83D\uDE00'` are the same string.
- **Identifiers**: `[A-Za-z_$][A-Za-z0-9_$]*`, ASCII only.
- **Keywords**: `true false null const if else while for break continue`. `let` is *not* a
  keyword (it isn't one in sloppy JS); it introduces a declaration only when followed by a
  binding name (§4). Other JS reserved words (`this`, `new`, `var`, `function`, …) are
  `Unsupported(syntax)` where an expression is expected, and a SyntaxError as variable names.

## 4. Syntactic grammar (M2, functions M6)

```
Script            := BodyItem*
BodyItem          := FunctionDeclaration | StatementListItem   (script and function bodies)
FunctionDeclaration := 'function' Identifier Params Body   (hoisted; not inside blocks)
Params            := '(' (Identifier (',' Identifier)* ','?)? ')'
Body              := '{' BodyItem* '}'
StatementListItem := Declaration | Statement
Declaration       := ('let' | 'const') Declarator (',' Declarator)* ';'
Declarator        := Identifier ('=' Expression)?          (const requires '=')
Statement         := ';'                                   (empty statement)
                   | '{' StatementListItem* '}'            (block)
                   | 'if' '(' Expression ')' Statement ('else' Statement)?
                   | 'while' '(' Expression ')' Statement
                   | 'for' '(' ForInit? ';' Expression? ';' Expression? ')' Statement
                   | 'break' ';' | 'continue' ';'          (only inside a loop of the same function)
                   | 'return' Expression? ';'              (only inside a function)
                   | Expression ';'
ForInit           := ('let' | 'const') Declarator (',' Declarator)* | Expression
Expression        := Identifier AssignOp Expression | Logical   (right-associative)
AssignOp          := '=' | '+=' | '-=' | '*=' | '/=' | '%=' | '**='
Logical           := Logical ('||' | '&&') Logical          (&& binds tighter than ||)
                   | Equality
Equality          := Equality ('===' | '!==') Relational | Relational
Relational        := Relational ('<' | '<=' | '>' | '>=') Additive | Additive
Additive          := Additive ('+' | '-') Mult | Mult
Mult              := Mult ('*' | '/' | '%') Exp | Exp
Exp               := Unary | Postfix '**' Exp               (right-associative)
Unary             := ('-' | '+' | '!') Unary | ('++' | '--') Unary | Postfix
Postfix           := Primary ('++' | '--')?                 (no line break before ++/--)
Primary           := Number | String | 'true' | 'false' | 'null' | Identifier
                   | 'function' Identifier? Params Body    (function expression)
                   | '(' Expression ')'
                   | Primary '(' (Expression (',' Expression)* ','?)? ')'   (call)
```

Notable rules, all matching JavaScript:
- `2 ** 3 ** 2` is `2 ** (3 ** 2)` = 512. `1 < 2 < 3` is legal (left-associative).
- `-`, `+` or `!` directly before `**` is a **SyntaxError** (`-2 ** 2`, `2 ** -2 ** 2`);
  `(-2) ** 2`, `2 ** -2`, `++x ** 2` and `x++ ** 2` are fine.
- Assignment and `++`/`--` targets must be identifiers, possibly parenthesised (`(x) = 1`);
  `1 = 2`, `x + 1 = 2`, `++1`, `(x + 1)++` are SyntaxErrors.
- `let` + binding name starts a declaration, even across a line break (`let\nx = 1`).
  A declaration where only a single statement is allowed (`if (c) let x = 1;`,
  `while (c) const y = 1;`) is a SyntaxError.
- **`break` / `continue`** (all three cases are distinct in JS):

  | input | meaning in JS | ZQJS |
  |---|---|---|
  | `break;` outside a loop | error | SyntaxError |
  | `break foo;` | jump to label `foo` | `Unsupported(labels)`, even outside a loop: `foo: { break foo; }` is valid |
  | `break\nfoo;` | ASI: `break; foo;` | `Unsupported(asi)` inside a loop; SyntaxError outside one |

Nesting deeper than `Limits.max_nesting_depth` (default 512) → `LimitExceeded(nesting_depth)`.
The limit bounds the parser's recursion (each parenthesis level costs two, each nested
statement or `=` one) and the depth of expression trees (operator chains).

A script whose bytecode exceeds `Limits.max_code_bytes` (default 64 MiB) →
`LimitExceeded(code_bytes)`; more than `Limits.max_constants` (default 2^20) distinct literals,
or as many distinct variable names → `LimitExceeded(constants)`. Both are reported before the
script runs (DESIGN_DECISIONS D32).

## 5. Semantics

### Values and globals (M3)
Values: `undefined`, `null`, booleans, numbers (IEEE-754 doubles), strings (UTF-16 code units),
native functions and (M6) closures. Globals: `undefined`, `NaN`, `Infinity`, and `print(a, b, …)`, which
writes `String(a) + ' ' + String(b) + … + '\n'` (lone surrogates are written as U+FFFD).
Calling anything other than a function throws a **TypeError** (after the arguments are
evaluated); reading an undeclared global throws a **ReferenceError**.

### Functions (M6), as in JavaScript
- **Calls:** the callee, then the arguments left to right, then the callable check. Missing
  arguments are `undefined`; extra ones are evaluated and dropped. `return;`, `return e;`, and
  falling off the end (`undefined`).
- **Declarations** at the top of a script or function body are hoisted *and initialised* on
  entry, so `f(); function f() {}` and mutual recursion work. Their names are mutable bindings.
- **Named function expressions:** the name is bound only inside the function, to the function;
  parameters and locals may shadow it.
- **Closures** capture *bindings*, not values: writes through one closure are seen by every
  other closure of the same binding, and a binding lives as long as any closure using it.
  Every execution of a block creates new bindings (`{ let x = …; f = function () { return x; }; }`
  run twice gives two independent `x`s).
- **`for (let …)`** gives each iteration its own copy of the head bindings: a closure created in
  an iteration keeps that iteration's value, even after later iterations or the update run.
- **Values:** functions compare by identity (`===`), are truthy, and convert to NaN. Converting
  one to a string, or comparing it with a string or another function, needs its source text:
  `Unsupported(function_to_string)`.
- **Limits:** more than `Limits.max_call_depth` (default 10,000) active calls →
  `LimitExceeded(call_depth)` (node: RangeError at about 11,000). The VM also limits the stack
  slots reserved by all active frames (`max_stack_slots`), the tree-walker its native recursion
  (`max_interpreter_depth`); which limit a runaway recursion hits first is engine-specific.

### Operators (M3), as in JavaScript
- Operands are evaluated left to right; `&&`/`||` short-circuit and return an operand value.
- `+` concatenates if either side is a string, otherwise adds numbers. `- * / % **` and unary
  `-`/`+` convert to numbers (`+'0x10'` is 16, `+'1_000'` is NaN, `+''` is 0).
- `<` `<=` `>` `>=` compare two strings by UTF-16 code unit, anything else as numbers.
- `===`/`!==`: same type and value; `NaN !== NaN`, `0 === -0`.
- `-0` is kept through arithmetic and prints as `0`.

### Bindings

**Static (checked now, by the resolver):**
- Each block, the script, and each `for` head is a scope. A `for` head scope encloses the
  body, so `for (let i;;) { let i; }` is legal.
- A `let`/`const` binding is visible from the *start* of its scope (hoisting), so
  `let x = 1; { x; let x = 2; }` refers to the inner `x`.
- Declaring the same name twice in one scope is a SyntaxError; shadowing an outer name is fine.
- At script level, `let`/`const` named `undefined`, `NaN` or `Infinity` is a SyntaxError
  (as in node). Inside a block or a `for` head they are ordinary names.
- Top-level bindings belong to the script; they are not shared between scripts (revisit at M9).
- A name with no declaration in scope is a *global*: reading it is allowed (M3: a
  ReferenceError if it doesn't exist), assigning to it is `Unsupported(global_assignment)`.

**Dynamic (enforced by the interpreter, checked against node in `tests/diff`):**
- **Temporal dead zone:** from scope entry until its declaration runs, reading or writing a
  binding throws a ReferenceError. `let x;` initialises to `undefined`. Each time a block is
  entered (e.g. each loop iteration) its bindings start uninitialised again.
- **`x = e`**: evaluate `e`, *then* the TDZ check, *then* the const check, then store.
  **`x op= e`** and **`++x`/`x++`**: read `x` (TDZ check) first, then evaluate the right side.
- **`const`**: writing to an initialised const binding throws a **TypeError**, only when the
  write executes (`if (false) c = 2;` is fine). It is never an early error.
- **`for (let …)`**: each iteration gets a fresh copy of the head bindings (see Functions).
